How it works, step by step.

What Freally OS keeps, why it has no network yet, and how to check that an image is ours.

    Contents
    1. Privacy

    Privacy

    Freally OS collects nothing. There is no telemetry, no crash upload, no account with us and no background connection: none of it was ever written.

    Your accounts and files stay on your computer, each account's home encrypted with a key only its password opens.

    The hardware report in Settings is text you can read before you send it, and it goes only where you send it.

    The tester sign-up, when it opens, keeps an email address and nothing else, only for the tester programme, and deletes it when you ask.

    This site loads nothing from other sites and runs no analytics.

    The network

    Freally OS can't make network connections yet. It has no network driver and no network stack: they arrive later on the road to 1.0, and the update check will ask before it ever connects.

    You can check it yourself: start it in a virtual machine with a network adapter, and watch the host's traffic for that machine (Wireshark will do). It sends nothing.

    Checking an official image

    Every official image is built from the public source, and the build is reproducible: the same commit gives the same bootloader and the same image, byte for byte, apart from the image's signature.

    To check one, check out the version's tag, run cargo xtask hashes --unsigned, and compare the two SHA-256 sums on its release line (the bootloader's, and the image's with its signature left out) with the ones published beside the image. They must be equal.

    Then the signature: the bootloader refuses any image not signed by a key it trusts, and says so on the screen. A changed byte anywhere in the image is caught before Freally OS starts.
