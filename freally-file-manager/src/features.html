What version 1.0 does

The copy engine

Byte-exact copies through each system's fastest path, with instant clones on file systems that support them. Huge folders stream through without filling memory, and you choose before a copy starts what happens to files that already exist: keep both, skip, overwrite, overwrite if newer, overwrite only if different, or ask.

Verify after copy

Eight checksums: CRC32, MD5, SHA-1, SHA-256, SHA-512, xxHash3-64, xxHash3-128 and BLAKE3. Each copy is read back and compared with the original, and a mismatch fails the file instead of passing unnoticed.

Hash, re-verify and checksum files

The Hash panel checks files against a checksum you paste. Re-verify compares a folder with its copy months later without writing a byte. Make .md5, .sha1, .sha256, .sha512, .b3 or .sfv files for a whole folder, and drop one on the window to check it.

Crash and reboot resume

A journal records each copy's progress. On the next launch the part already written is checked against its hash, and the copy continues from there.

History, re-runs and undo

Every job is recorded. Run any of them again, retry only the files that failed, export a signed report, or undo the last copy or move: undone copies go to the Recycle Bin or Trash, never straight to deletion.

Sync and live mirror

Two-way sync, a mirror in either direction, or contribute-only, with conflicts kept as two files for you to choose between. A live mirror watches a folder and syncs every change you save.

A built-in file server

Serve any folder over WebDAV, HTTP, an S3-compatible API or SFTP, from Settings or the freally serve command, read-only if you like, behind a token or a password, with a Prometheus metrics endpoint.

Snapshots and backups

A deduplicating repository stores each version of a file once. Browse the timeline, restore any snapshot, back up chosen folders on demand, and bring in repositories from restic, Borg or Kopia.

Rescue a failing disk

Salvage copies whatever can still be read of a file on a failing drive, fills the unreadable spots with zeros so the rest keeps its place, keeps a map of the gaps, and retries only those gaps on a later run.

Nothing quietly lost

Sparse files stay sparse, and alternate data streams, extended attributes and the downloaded-from-the-internet mark travel with each file. A file locked by another program on Windows can be copied from a snapshot.

Part of your desktop

Copy and move from the right-click menu in Explorer, Finder, Nautilus, Dolphin and Thunar, paste through it from anywhere with Ctrl+Shift+V, and schedule saved jobs in your system's own scheduler.

A command line for scripts

The freally command copies, moves and verifies, plans a job before running it, serves folders and imports backups, and reports in JSON lines with documented exit codes.

The short version

The short version: only Freally File Manager has all of it. None of the six lists a server for WebDAV, S3 or SFTP, or a way to rescue files from a failing drive, on its maker's own pages, and of the six only GoodSync documents detecting a sync conflict.

Where they win

Where they win: Directory Opus, Total Commander and ForkLift let you browse and organise all your folders in their own windows, while Freally File Manager 1.0.0 works on the files you hand it. TeraCopy and Directory Opus can securely delete files, and ForkLift, Beyond Compare and GoodSync copy to cloud storage; Freally File Manager 1.0.0 does neither. TeraCopy also offers more checksums: 17 against eight.

Why it is built the way it is

Byte for byte, or a failure

A copy is the same bytes as the original, or it is reported as a failure. And a file that changes while it is being read is flagged, copied again or failed, as you choose, rather than passed off as a clean copy.

The system's own fast paths

It asks Windows, macOS and Linux to copy each file the fastest way they know, and clones files instantly where the file system allows, instead of pushing every byte through a loop of its own.

Nothing destructive by accident

A move deletes the original only after the copy has succeeded, undo sends files to the Recycle Bin or Trash rather than deleting them, and undo never touches a file that has changed since it was copied.

It stays on your machine

No telemetry and no account. Your files go only where you send them, and telemetry cannot even be switched on by editing the settings file.

No AI

Everything it decides comes from ordinary, predictable code: checksums, sizes and timestamps. There is no machine-learning library in it.

The limits, stated plainly

A feature list that hides its gaps is not worth reading. Everything above is in version 1.0.0, and this is what it does not do.

What 1.0 does not do

  • It does not verify a copy until you switch verification on in Settings → Transfer.
  • Jobs cannot be reordered in the queue: each one starts as soon as it is added.
  • Portable mode keeps settings and profiles beside the app, but history, the resume journal and saved cloud passwords stay on the computer it runs on.
  • It cannot securely shred files: Settings → Secure delete is there, but nothing in 1.0.0 deletes through it.
  • It cannot copy to cloud storage: you can add and test cloud accounts in Settings → Remotes, but no copy goes to them yet.
