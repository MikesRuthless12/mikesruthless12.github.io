Changelog

All notable changes to Freally File Manager, newest first. Every version here is built and tagged; there are no downloads on this site yet.

[1.0.0] — 2026-08-22 — The correctness release

Every feature from 0.22.0 is here. What changed is a full review of the code, section by section, and the fixes that came out of it. Several of them could lose data without ever showing an error.

Fixed

  • Shortcut folders. Copying a folder that is itself a shortcut (a symbolic link or a junction) copied nothing and reported success, and in sync the same flaw could empty the other side. Such a folder is now refused, with the reason.
  • Cancelling. Cancelling a large folder copy could hang instead of stopping. A copy can now be cancelled at any point.
  • The S3 server. Files uploaded by the AWS command line or an AWS library were stored damaged, and uploads larger than about 8 MB failed outright. Both now arrive byte for byte, and a cut-off upload is refused instead of stored.
  • Sync databases. A sync pair whose database sat inside one of its own folders treated that database as a file to sync, and could delete it in the middle of a run.
  • SFTP. SFTP remotes never connected: every connection test failed, whatever the settings. They connect now.
  • Encryption. Encryption could fall back to writing plain files when its key could not be prepared. It now stops the job instead.
  • Read-only server. One kind of request could still write to a server set to read-only. None can now.
  • Progress. A resumed scan reported the wrong number of files, so progress bars were wrong in both directions.
  • Cloud sign-in. Signing in to a cloud account could fail for no visible reason, and abandoning a sign-in leaked a thread each time.
  • Known hosts. An SFTP server pinned in a known_hosts file was refused whenever it offered any key type but the first one listed, which is most of the time.
  • Notifications. ntfy notifications arrived as raw code instead of the message.
  • Dialogs. Escape closed the wrong dialog when two were open, and a few Settings panels were laid out wrongly.
  • The administrator prompt (security). On Linux and macOS, another program running as you could swap in its own connection while the password prompt was open, and be the one running as administrator once you approved. The prompt can no longer be taken over that way.
  • Capital letters. On Windows and macOS, Photo.jpg and photo.jpg are one file, but sync treated them as two, copied each over the other, and could then delete the survivor. They are one file again.
  • Network drives. Serving a folder that lives on a network drive no longer lets one slow response hold up every other request.
  • The helper. The installers left out the small helper that does anything needing administrator rights, so on an installed copy those actions failed, such as retrying a copy refused for permissions or changing the right-click menu. The helper now ships beside the app.
  • Check for updates. It failed every time, on every system. It now reads the list of updates published with each release.
  • Release notes. The Updates pane repeated the changelog link four times and showed it as dead text. The notes now appear once, with a link that opens in your browser.
  • Documentation that promised behaviour the code did not have was corrected.

[0.22.0] — 2026-08-19 — Hashing, reports, scheduling and portability

Added

  • Hash inspector. Hash any files or folders with any of the eight algorithms, paste a checksum to compare against, or compare two files. On Windows it is also in the right-click menu.
  • Copy reports. Export any finished job as a printable HTML report, CSV or JSON, with every file's checksum, size and status, and sign it with your own key if you like, so anyone can check it without Freally File Manager.
  • Re-verify. Compare a folder with its copy again, months later, without writing a byte: what matches, what differs, what is missing and what was added.
  • Filename doctor. Before a copy, find names the destination cannot hold, such as reserved names, characters it does not allow, trailing dots and spaces, paths that are too long and names that differ only in capital letters, and rename them.
  • Copy from a list. Import a list of paths from a TXT, CSV or JSON file as the files to copy, flat or keeping their folders.
  • Plan reports. Export what a copy will add, replace, skip or find in conflict, before a single byte moves.
  • Salvage. Copy what can still be read of a file on a failing drive, fill the unreadable spots with zeros, keep a map of the gaps, and retry only the gaps later.
  • One prompt for many files. When many files were refused for permissions, approve one list and retry them all through a single administrator prompt.
  • Schedules. Create, edit and remove entries in your system's own scheduler (Task Scheduler, launchd or systemd), with the next run time shown and no administrator rights needed.
  • Drive queues. Correct the drive detection when it is wrong: make folders share one queue, or split them apart, with a number of workers for each.
  • Prioritize. Pause the other running jobs while one finishes, then resume exactly those.
  • Favourites. Bookmark sources, destinations and source-to-destination pairs, and keep a recent pair as a favourite in one click.
  • Portable mode. --portable, or a marker file beside the app, keeps settings and profiles beside it. History, the resume journal and saved cloud passwords still stay on the computer, and Settings says so.
  • Accessibility. Escape closes the topmost dialog from anywhere, reduced motion is honoured everywhere, focus is always visible, and a screen reader hears the running, done and failed counts.
  • Source-stability guard. A file that changes while it is being copied is flagged, copied again once, or failed, as you choose.
  • Start at login. Start minimized to the tray, so the right-click menu, the paste shortcut and schedules work from the moment you sign in.

Fixed

  • Settings could discard your data. Saving Settings reset pinned tray destinations, repositories, cloud accounts, sync pairs and more to their defaults. Every group now survives a save, and a test makes sure of it.

[0.20.0] — 2026-07-20 — Safety nets

Added

  • Undo. Ctrl+Z, or Undo on a history row, shows what reversing the newest copy or move will touch, then does it. Copied files go to the Recycle Bin or Trash, and only if they still match what was copied.
  • Delete to the Recycle Bin or Trash, and an option to send a moved file's original there instead of deleting it.
  • Retry failed. Copy again only the files that failed in a job, or export their list.
  • Two new choices for existing files. Overwrite only if the content differs, or skip if identical and ask otherwise.
  • Eject. Safely remove the drive a job wrote to.
  • No sleep while copying. The computer stays awake while any job runs.
  • Checksum files. Make .md5, .sha1, .sha256, .sha512, .b3 or .sfv files for a whole folder, and drop one on the window to check every file it lists.
  • Take over Windows' copy. Optionally route Explorer's own copy and paste through Freally File Manager, with a one-click way back. Every paste offers a plain system copy or a verified one.
  • Licence agreement. It is shown the first time the app opens.

[0.19.85] — 2026-07-01 — The Library and backup tools

Added

  • The Library. One timeline of every snapshot, with how much is stored against how much it represents: back up chosen folders, and restore any snapshot to wherever you choose.
  • Compressed, compacted storage. Snapshots can be compressed, and maintenance reclaims and compacts the space nothing uses any more, with every long task shown in Tasks.
  • Compare and reports. Compare two snapshots, and see statistics and charts of the repository.
  • Repository keys. Several passwords for one repository, and a recovery key.
  • Replicate. Copy a repository to a second place, sending only what the other side lacks.
  • Other backup tools. Bring in a restic, Borg or Kopia repository with freally migrate, and write one back out with freally export.

Fixed

  • Fifteen problems found in a full review, including ways a backup could lose data without saying so.

[0.19.84] — 2026-06-27 — The first release

  • Byte-exact copy and move through each system's fastest path, with instant clones on file systems that support them, and folders of any size streamed without filling memory.
  • Verify after copy with eight checksums, from CRC32 and xxHash3 to SHA-256 and BLAKE3.
  • Pause, resume and cancel any job, choose what happens to files that already exist, and retry a file refused for permissions with administrator rights.
  • Resume after a crash or a reboot from a journal of each copy's progress.
  • History and totals: every job recorded, filtered, exported as CSV and run again with one click.
  • Filters: include and exclude patterns, sizes, dates and file attributes.
  • Two-way sync with conflict detection, mirror and contribute modes, and a live mirror that syncs every saved change.
  • Speed limits, fixed or on a schedule.
  • Nothing quietly lost: sparse files, alternate data streams, extended attributes and the downloaded-from-the-internet mark are kept, and a locked file on Windows can be copied from a snapshot.
  • Your desktop: right-click menus on Windows, macOS and Linux, a paste shortcut that works from anywhere, and a tray icon.
  • A file server over WebDAV, HTTP, an S3-compatible API or SFTP, with freally serve for computers without a screen.
  • The freally command line, with JSON-lines output, documented exit codes, and jobs you can plan before running them.
  • Why is it slow? A badge names what is holding a copy back.
  • 18 languages, Arabic right to left.
